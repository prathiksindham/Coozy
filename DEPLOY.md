# Deploying Coozy

The app is a single long-lived Python server (`server.py`, standard library
only for the core). Host it anywhere that runs a persistent Python process —
**Render** is the easiest and there's a Blueprint (`render.yaml`) ready to go.

> Note: it is **not** a good fit for Vercel/Netlify serverless — it keeps state
> in a SQLite file and runs a long-lived server, neither of which fits the
> per-request serverless model.

## Deploy to Render (free tier)

1. Push to GitHub (already done — branch `coozy`).
2. Go to https://render.com → sign in with GitHub.
3. **New +** → **Blueprint** → pick the `Coozy` repo → Render reads `render.yaml`.
4. It will ask for the `sync: false` env vars. **All are optional** — leave any
   blank to skip that feature:
   - `GOOGLE_CLIENT_ID` — Google sign-in + saved playlists
   - `GEMINI_API_KEY` / `GROQ_API_KEY` / `LLM_PROVIDER` — AI persona + lyrics AI fallback
   - `LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` — voice rooms
   - `SESSION_SECRET` is auto-generated by Render.
5. **Create** → wait for the build. You get a URL like `https://coozy.onrender.com`.

The core music player, YouTube search, and lyrics work with **no keys set**.

## After deploy

- **Google sign-in:** in Google Cloud Console → your OAuth client → add your
  Render URL (e.g. `https://coozy.onrender.com`) to *Authorized JavaScript
  origins*, or sign-in will be rejected.
- **Free-tier caveats:** the instance sleeps after ~15 min idle (first request
  is slow to wake) and its filesystem is ephemeral — the SQLite DB (logins,
  playlists) resets on redeploy/restart. For durable storage, add a Render
  **Disk** mounted at `./data` (paid) or move to an external DB.
- **Wake-word / vosk model** downloads itself on first boot (~40 MB), so it
  isn't committed to the repo.

## Run locally

```bash
pip install -r requirements.txt   # optional extras; core needs nothing
python3 server.py                 # http://localhost:4747
```
